## 완성까지의 로드맵

**"완성"의 정의**: 회원/차량/정비 이력을 관리하는 백엔드 API + 그걸 실제로 쓸 수 있는
프론트엔드 웹앱까지. 배포(서버 인프라, 도메인, CI/CD)는 범위 밖 — **로컬에서 완전히 동작하는 것**까지가 목표다.

**플랫폼은 웹 하나다** (2026-09-16 확정). iOS/Android 네이티브 앱은 만들지 않고, 세 개를
병행하지도 않는다. 근거와 "다시 꺼낼 조건"은 `HISTORY.md` 의 2026-09-16 항목에 적어 뒀다.
한 줄 요약: **브라우저가 못 하는 일을 이 앱이 아직 하나도 안 한다.**

- **Phase 1 — 백엔드 마무리** (완료)
  프론트가 호출할 API 표면 완성. 단건 조회, 날짜 기준 다음 정비, 페이지네이션, CORS, API 문서화.

  회원가입/로그인/로그아웃, 로그인 상태 전역 관리, 보호 라우트.

## Phase 6 — 다듬기

코드는 사실상 끝났다. 브라우저 확인은 2026-10-10 에 1~4회차를 한 번에 돌았고, **실제 폰의 손가락·주소창으로만 판단할 넷**이 남았다.

**화면을 크게 고치거나 새로 만든 작업이 열 번 넘게 연속으로 쌓였다.** 재설계(9/11) →
모서리 각지게 → 홈 통계·차트 → 편집 레이아웃 → 모션 재조정 → 모바일 최적화 →
주유 기록·연비 → 정비 종류 15개 → 날짜 드럼 휠 → 홈 요약 API → 연비 초기화 →
빠진 기록 감지(9/17). **전부 `tsc -b` / `oxlint` / `vite build` 통과만으로 끝냈고,
실제 화면은 아직 아무도 본 적이 없다.** 여기에 코드를 더 쌓으면 깨진 게 나왔을 때
어느 작업에서 깨졌는지 못 찾는다.

**체크리스트는 그 사이에 두 번 낡았다.** 기능이 붙을 때 항목을 같이 안 적으면, 한 바퀴를
다 돌고도 새 기능은 한 번도 안 본 채로 끝난다. 2026-09-17 에 훑어 10건을 고치고 14건을 더했다
(연비 초기화 · 이상 연비 · 빠진 기록 안내 · 과거 기록 입력 · 최근 활동 · 차량별 평균 연비).
**앞으로 화면에 무언가를 더할 때는 6-B 에 줄을 같이 넣는다.**

**Phase 2~5 에 흩어져 있던 "브라우저에서 확인" 네 줄을 여기로 합쳤다.** 같은 말이 네 군데
있으면 어디까지 봤는지 알 수가 없다.

### 볼 화면은 12개가 아니라 15개다

라우트는 12개지만(`/` `/privacy` `/terms` `/login` `/signup` `/forgot-password` `/reset-password`
`/vehicles` `/vehicles/new` `/vehicles/:vehicleId` `/me` `*`), **`/` 가 세 얼굴을 갖는다** —
비로그인 랜딩 / 로그인+0대 등록 권유 / 로그인+차량 있음 통계.
`/forgot-password` 도 **보내기 전과 보낸 뒤 둘**이고, `/reset-password` 는 **토큰이 있을 때와
없을 때 둘**이다. `*` 는 화면이 아니라 `/` 로 보내는 리다이렉트다.
그래서 눈으로 볼 상태는 **15개**이고, 여기에 각 화면의 로딩·빈 상태·에러가 더 붙는다.

※ 프로필 경로는 `/profile` 이 아니라 **`/me`** 다.

### 규칙: 발견한 건 적어만 두고 그 자리에서 고치지 않는다

한 바퀴 다 돌고 나서 모아서 고친다. 중간에 고치면 그 수정 때문에 뒷부분이 또 달라져서,
지금 보고 있는 게 원래 그런 건지 방금 내가 만든 건지 구분이 안 된다.
발견한 것은 **6-F 표에 줄을 추가**한다.

### Phase 6 과의 순서

Phase 6 은 "눈 확인 전에 코드를 더 쌓지 않는다" 를 전제로 한다. 계획은 7-3 부터 6-B 뒤였지만

상태**다 — 6-B 항목의 한국어 문구는 한국어 계정 기준으로 그대로 맞고, 영어·단위는 7-H 에서 따로 본다.

### 먼저 정해 둔 것 (지켜야 할 것)

1. **저장 단위는 km · L 그대로다. 변환은 화면이 한다.**
   대안은 "입력한 단위 그대로 + 단위 칸" 인데, 그러면 연비 계산·합산마다 변환이 끼고 단위가 섞인
   기록은 더할 수 없다. 정규화해 두면 **서버의 계산과 임계값이 한 줄도 안 바뀐다** —
   `FuelAnomaly` 의 50km/L · `InputLimits.MAX_ODOMETER` · `ServiceType` 주기 · 프런트 `looksBigJump`
   가 전부 km·L 기준 그대로 유효하다(프런트는 **변환한 뒤에** 판정한다).
   반올림 왕복(마일 → km 정수 → 마일)은 km 가 마일보다 촘촘해서 원래 값으로 돌아온다. 7-5 에서 테스트로 고정한다.
2. **단위 체계는 네 값이다** — 거리·부피·연비 표기를 따로 고르게 하지 않는다. 조합이 나라마다 정해져 있다:

       KM_PER_L      km · L · km/L        한국
       L_PER_100KM   km · L · L/100km     캐나다·호주·유럽
       MPG_US        mi · US gal · MPG    미국
       MPG_UK        mi · L · MPG(영국)    영국 (주유소는 리터, 연비는 영국 갤런)

3. **금액은 최소 단위(센트) 정수, 통화 코드(ISO 4217, 3자)는 기록마다** (2026-09-29 확정).
   `BigDecimal` 도 되지만 금액은 더하기만 하므로 정수가 단순하다.
   **원화는 소수 자리가 0 이라 지금 저장된 값이 이미 최소 단위다** — 마이그레이션은 통화 칸을 `KRW` 로
   채우는 것뿐이다. **기록 한 건은 `int` 그대로 둔다** — 상한(최소 단위 1억)이 `int` 한계(21억)보다 한참
   아래라 넓힐 이유가 없고, 합계는 이미 `long` 이다.
   **통화를 사용자가 아니라 기록에 둔 이유**: 사용자에만 두면 설정을 바꾸는 순간 옛 기록 50,000원이
   $500.00 으로 조용히 바뀐다. 대가로 합계·차트는 통화별로 나눠야 한다(7-3b).
4. **"오늘" 은 사용자의 시간대로 계산한다.** 서버가 서울로 고정돼 있으면 한국보다 앞선 곳
   (뉴질랜드 UTC+13)에서 오늘 기록이 미래로 판정돼 400 이 난다 — 한국에서 매일 오전 9시까지 겪었던 것과 같은 모양이다.
   시간대는 IANA 이름(`America/Los_Angeles`)으로 사용자에게 저장한다. 가입할 때 브라우저 값
   (`Intl.DateTimeFormat().resolvedOptions().timeZone`)을 받는다.
   **JVM 기본 시간대(`Asia/Seoul`)는 이 단계에서 건드리지 않는다.** "오늘" 을 사용자 기준으로 옮기면

## 타던 차 온보딩 (2026-09-30)

배포한다면 새 차보다 **이미 타던 차를 등록하는 사람**이 대부분이다. 그 사람이 첫날부터 쓸모를 보게 하고,
쓰다 보면 기록이 쌓이게 한다. 튜토리얼 팝업을 따로 두지 않고 **실제 입력이 곧 안내**가 되게 했다.
코드는 끝났고 확인은 6-B 의 B-17-1 · B-33-1 ~ B-33-4 로 합쳤다.

**정한 것 (지켜야 할 것)**

1. **등록할 때 현재 주행거리를 받는다(필수).** 0 에서 시작하면 첫 주유부터 급증 확인이 어긋나고
   (기준 0 은 판정 제외라 조용히 통과), 다음 정비의 주행거리 기준이 의미가 없다.
2. **"모르는 값" 은 비운다 — 정비 비용과 그때 주행거리.** 주유의 주유량·금액(9/23)과 같은 규칙이다.
   0 으로 채우면 "0원에 갈았다" 는 다른 사실이 되고 합계가 낮아진다. 합계만 `costOrZero()`,
   한 건 표시는 `—`. 주행거리가 비면 다음 정비는 **날짜 기준만** 계산한다.
   **별도 "시작 시점" 테이블을 만들지 않은 이유**: 기억해 낸 정비도 실제로 있었던 정비라 이력에 남는 게 맞고,
   나중에 영수증을 찾으면 그 기록에 비용만 채우면 된다. 따로 두면 옮길 길이 없다.
3. **날짜는 "3·6개월 전·1년 전" + 날짜 지정.** 저장은 여전히 날짜 하나 — "대략" 이라는 정밀도는 저장하지 않는다.
   년·월만 저장하는 방식은 날짜 컬럼·계산·표시가 전부 바뀌어 뒀다.
4. **안내는 차량 상세의 체크리스트 카드.** 완료 판정은 저장된 기록 건수로만 한다(진행 상태를 따로 저장하면
   기록을 지웠을 때 거짓말을 한다). 마법사(단계별 화면)를 안 쓴 이유: 건너뛴 사람이 돌아올 자리가 없다.
